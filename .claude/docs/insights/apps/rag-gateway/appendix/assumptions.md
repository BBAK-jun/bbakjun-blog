## Executive Summary

본 문서는 RAG Gateway의 비즈니스 분석에 사용된 모든 가정사항을 명시합니다. 이러한 가정들은 **실제 데이터가 부족한 경우 보수적인 추정**을 사용하며, **데이터 수집 후 지속적인 업데이트**가 필요합니다.

## Assumptions by Category

### 1. 테스트 ROI 계산

#### 가정 1.1: 프로덕션 버그 수정 비용
- **가정**: 프로덕션 버그 수정 비용이 테스트 비용의 10배
- **근거**: 일반적인 소프트웨어 엔지니어링 연구 (Boehm, 1981)
- **변수**:
  - 테스트 비용: 월 4시간 (테스트 작성 및 유지보수)
  - 버그 수정 비용: 월 20시간 (프로덕션 버그 수정)
  - 개발자 시급: $50/시간
- **ROI**: (20시간 - 4시간) / 4시간 = **400%**
- **불확실성**: 중간 (실제 데이터 필요)

#### 가정 1.2: 장애 감소 추정
- **가정**: 월 4회 장애 발생 (테스트 도입 전) → 월 1-2회 (테스트 도입 후)
- **장애 감소율**: 50-75% 감소
- **근거**: 업계 평균 (테스트 커버리지 70-80% 시)
- **불확실성**: 중간 (실제 장애 데이터 필요)

#### 가정 1.3: 회귀 버그 발견 시간
- **가정**:
  - 수동 테스트: 1-2일 (배포 후 사용자 리포트)
  - 자동화된 테스트: 5-10분 (CI/CD 파이프라인)
- **단축율**: 95% 단축
- **근거**: CI/CD 파이프라인 평균 실행 시간
- **불확실성**: 낮음 (측정 가능)

### 2. 비용 분석

#### 가정 2.1: 쿼리 볼륨
- **가정**: 월 1,000-100,000 쿼리 (일반적인 기술 블로그)
- **근거**: 유사 블로그의 검색 사용량
- **분포**:
  - 10%: 1,000 queries/month
  - 60%: 10,000 queries/month
  - 30%: 100,000 queries/month
- **불확실성**: 높음 (실제 데이터 필요)

#### 가정 2.2: 토큰 사용량
- **가정**: 평균 800 tokens/query
  - 100 tokens: 쿼리 임베딩
  - 400 tokens: 검색된 컨텍스트
  - 300 tokens: LLM 출력
- **근거**: RAG 시스템 평균 (업계 표준)
- **불확실성**: 중간 (실제 측정 필요)

#### 가정 2.3: 캐시 적중률
- **가정**:
  - 임베딩 캐시: 90% 적중률
  - 답변 캐시: 40% 적중률 (도입 시)
- **근거**: 기술 블로그의 반복 질문 패턴
- **불확실성**: 중간 (실제 측정 필요)

#### 가정 2.4: GLM 품질
- **가정**: GLM-4.6이 OpenAI gpt-4o-mini와 동등한 품질 (한국어)
- **근거**: Zhipu AI 벤치마크 (검증 필요)
- **불확실성**: 높음 (A/B 테스트 필수)

---

### 3. 운영 효율

#### 가정 3.1: 장애 대응 시간
- **가정**:
  - 현재: 평균 30분 (장애 발생 → 해결)
  - 개선 후: 평균 10분 (헬스 체크 API 활용)
- **단축율**: 67% 단축
- **근거**: 모니터링 도구 도입 효과 (업계 평균)
- **불확실성**: 중간 (실제 측정 필요)

#### 가정 3.2: 운영 업무 시간
- **가정**:
  - 현재: 월 20시간 (수동 모니터링, 장애 대응)
  - 개선 후: 월 10시간 (자동화된 모니터링)
- **절감율**: 50% 절감
- **근거**: 모니터링 자동화 효과
- **불확실성**: 중간 (실제 측정 필요)

### 4. 개발 속도

#### 가정 4.1: 기능 출시 주기
- **가정**:
  - 현재: 2주 (수동 테스트 포함)
  - 개선 후: 1주 (자동화된 테스트)
- **단축율**: 50% 단축
- **근거**: CI/CD 파이프라인 도입 효과
- **불확실성**: 낮음 (측정 가능)

#### 가정 4.2: 리팩토링 안정성
- **가정**: 테스트 커버리지 80% 시 리팩토링 장애율 5% 미만
- **근거**: 업계 베스트 프랙티스
- **불확실성**: 중간 (실제 측정 필요)

### 5. 사용자 행동

#### 가정 5.1: 콘텐츠 발견율 개선
- **가정**: RAG 도입 시 콘텐츠 발견율 30% 개선
- **근거**: 의미론적 검색 vs 키워드 검색 (업계 연구)
- **불확실성**: 높음 (실제 A/B 테스트 필요)

#### 가정 5.2: 사용자 만족도
- **가정**: AI 답변 만족도 70% (좋아요/싫어요)
- **근거**: 유사 RAG 시스템 평균
- **불확실성**: 높음 (실제 피드백 필요)

#### 가정 5.3: 출처 클릭률
- **가정**: 답변의 출처 클릭률 40%
- **근거**: 정보 검색 시 출처 확인 비율
- **불확실성**: 중간 (실제 측정 필요)

### 6. 저장소 용량

#### 가정 6.1: Qdrant 저장소
- **가정**: 1GB = ~10,000 블로그 게시물
- **계산**:
  - 1 chunk ≈ 1,200 characters ≈ 3KB (vector + metadata)
  - 1 post ≈ 20 chunks ≈ 60KB
  - 1GB ≈ 17,000 posts
- **불확실성**: 낮음 (계산 가능)
